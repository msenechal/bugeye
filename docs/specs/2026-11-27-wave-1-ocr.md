# Wave 1: OCR word map and text map

**Status:** draft for approval · **Date:** 27 November 2026 · **Process:** brainstorm → spec (this) → plan → execution → final review → fix pass → Mac batch

This epic rebuilds the layer every later text feature reads (`design/05` B2 "Word-level reading", `design/07` §2.2–2.3): Vision OCR at word level behind the `TextReader` port, the portable **word map** (`TextMap`: lines and words with pixel boxes), the **text map** (`TextLayout`: the map as plain text with rows and indentation), find matching, and a cached, identity-checked per-capture service. The sweep, find, exact text, search and Capture Text (Wave 2) consume it. It runs as one of the parallel Wave 1 sessions (`design/14` R1, §4) on Wave 0's skeleton. Nothing in it is user-visible.

## 4. The word map (`TextCore`)

```swift
public struct TextWord: Hashable, Codable, Sendable { var text: String; var range: Range<Int>; var box: Rect2D }
public struct TextLine: Hashable, Codable, Sendable {
    var text: String; var box: Rect2D; var words: [TextWord]; var confidence: Double
    var row: Int                       // index of its row in reading order (§4.2)
}
public struct TextMap: Hashable, Codable, Sendable {
    var width: Int; var height: Int    // the pixel space of every box: the read image, top-left origin
    var lines: [TextLine]              // reading order
    var isEmpty: Bool
}
public struct TextMatch: Hashable, Sendable { var line: Int; var range: Range<Int>; var box: Rect2D }
```

All ranges count `Character`s of `TextLine.text`. All boxes are `Rect2D` in the map's pixel space.

### 4.1 Normalisation (`TextMapBuilder`, from `[OCRLine]` in one image's pixels)

For each line:
1. Text → NFC (`precomposedStringWithCanonicalMapping`). Character counts don't change.
2. Trim leading and trailing whitespace and newlines. Shift word ranges by the leading count, clip them to the trimmed text, and drop words left empty.
3. If the text is empty, drop the line.
4. Clip the line box to `0..<width × 0..<height`. Drop the line if the clipped box is empty.
5. Words: drop a word whose range is out of bounds, empty or overlaps an earlier kept word. Trim whitespace off the word's slice, adjusting its range, and drop it if empty. Clip its box to the image, and drop it if empty. `TextWord.text` is the slice.
6. Confidence is clamped to 0…1.

### 4.2 Reading order

1. Sort the lines by (minY, minX, input order).
2. Group them into rows. A line joins the current row when `sameLine(rowFirst, line)`: their vertical overlap is ≥ 0.5 × the smaller height. Otherwise it starts a new row. The comparison is always with the row's **first** line (`design/05` B3).
3. Within each row, sort by (minX, input order).
4. `lines` = rows in order, flattened. Each line's `row` is its row's index.

### 4.3 `box(for range:)` on a line

- `nil` when the range is empty or holds only whitespace.
- A line with no words is treated as one word covering all of `text` with the line's box.
- For each word the range overlaps: the whole box if the word is fully inside the range. Otherwise the box is cut **in proportion to characters**: x from `minX + width·(start − w.start)/w.count` to `minX + width·(end − w.start)/w.count`, full height. Example: `customer` inside `customers` is 8/9 of its width.
- Non-whitespace characters in the range that no word covers (Vision couldn't box them) get a slice of the line box, at `line.width / text.count` per character.
- The result is the union of these pieces.

### 4.4 Find (`matches(of:matchCase:)`)

- **Fold** each `Character` on its own: canonical decomposition, remove scalars whose general category is `nonspacingMark`, then `lowercased()` unless `matchCase`. The query is folded the same way. This is portable and identical on Linux and macOS, with no `.diacriticInsensitive`.
- A match is a run of whole consecutive characters of one line whose folded forms, concatenated, equal the folded query. It starts and ends on character boundaries. Matches never cross lines, but may span words.
- Matching runs left to right, without overlaps, line by line in reading order. A match whose `box(for:)` is nil is skipped.
- An empty or whitespace-only query has no matches.

### 4.5 Mapping between pixel spaces

`TextMap.mapped(scale: Double, offset: Point2D, width: Int, height: Int)`: every box becomes `(x·scale + offset.x, y·scale + offset.y, w·scale, h·scale)`, then normalisation steps 4–5 run against the new size. Used for strip mapping (scale `1/s`, offset `(0, stripStart)`) and, later, for document pixels in the editor (offset `−imageOrigin`, `design/07` §2.9).

### 4.6 The text map (`TextLayout`)

- **`lines(_ map) -> String?`:** one output line per row: the row's line texts joined with one space, left to right. Then indentation: `charWidth` = the median over all lines of `box.width / text.count` (the mean of the two middle values when the count is even). Each row gets `round((row.minX − leftmost row minX) / charWidth)` leading spaces, rounding half away from zero, or none if `charWidth ≤ 0`. Rows are joined with `\n`. With no rows the result is nil.
- **`summary(_ text) -> String`:** the first line with spaces trimmed. If it is longer than 60 characters, it becomes its first 60 characters plus `…`. If the text has more than one line, ` (N lines)` is appended, N being the number of lines. Example: `Traceback (most recent call last): (12 lines)`.

## 5. Reading

### 5.1 Strips (`StripPlan`)

`scale(pixelsPerPoint)` = 2 when < 2, else 1. Rows `R = 4000 / scale`, overlap `O = 200 / scale` (integers: 4000/200 or 2000/100).

`strips(height H)`: if `H ≤ R`, one strip `0..<H`. Otherwise `s = 0`, then repeat: append `s..<min(s + R, H)`, stop if `s + R ≥ H`, else `s += R − O`. Examples: 8,200 px at 2× → `0..<4000, 3800..<7800, 7600..<8200`. 4,500 px at 1× → `0..<2000, 1900..<3900, 3800..<4500`.

### 5.2 Enlargement (`PixelResample.enlarged2x`)

Output `2W × 2H`. The output pixel `(x, y)` samples the source at `((x + 0.5)/2 − 0.5, (y + 0.5)/2 − 0.5)`, clamped to the image, interpolating each channel bilinearly and rounding half up. Rows are cropped from an in-memory buffer by `PixelResample.rows(_:)`, as copies.

### 5.3 `TextMapReader.read(_ source, pixelsPerPoint) async throws -> TextMap`

`source` is `.buffer(PixelBuffer)` or `.file(URL)` (decoded strip by strip through `ImageFileReader.pixels(of:rows:)`).
1. Get the size, plan the strips (§5.1).
2. For each strip, in order: `Task.checkCancellation()`; get its rows; enlarge if the scale is 2; call `TextReader` under the strip timeout (T9: 10 s on an injected `Clock`; when it expires, the read's task is cancelled and `TextMapError.timedOut(strip:)` is thrown); build the strip's map (§4.1) in strip pixels; map it back (§4.5, scale `1/s`, offset `(0, start)`, the full image size).
3. Merge (§5.3.1), then reading order (§4.2).

Errors: `TextMapError.timedOut(strip: Int)`, `.unreadable(URL)`, `.recognitionFailed(String)` (wrapping a reader error) and `CancellationError`. There is no partial result.

#### 5.3.1 Strip merge

For each strip `i > 0`, with top overlap band `[start, start + O)` in image rows:
- a line of strip `i` entirely inside the band (`minY ≥ start`, `maxY ≤ start + O`) is dropped, because the strip above has it;
- a line of strip `i` that starts inside the band (`minY < start + O`) and ends below it **replaces** every kept line from the strips above whose box intersects it with positive area, because the strip edge cut those;
- every other line of strip `i` is kept.

### 5.4 The per-capture store (`CaptureTextMaps`, actor)

```swift
public struct TextMapKey: Hashable, Sendable { var id: CaptureID; var fingerprint: FileFingerprint }
public struct CaptureTextMap: Hashable, Sendable { var key: TextMapKey; var map: TextMap }
public enum TextMapError: Error, Hashable { case timedOut(strip: Int), unreadable(URL), recognitionFailed(String),
                                            captureGone(CaptureID), changedWhileReading(CaptureID) }

public actor CaptureTextMaps {
    public init(reader: TextMapReader, files: any ImageFileReader, capacity: Int = 200,
                wanted: @escaping @Sendable (CaptureItem) -> Bool = { $0.kind == .screenshot },
                log: @escaping @Sendable (TextLogLine) -> Void)
    /// Bus events, in publication order.
    public func handle(_ event: CaptureEvent)
    /// The capture's current map: cached, joined, or read now (ahead of background reads).
    public func map(for item: CaptureItem) async throws -> CaptureTextMap
    /// The last stored map for the capture, without touching the file.
    public func cached(_ id: CaptureID) -> CaptureTextMap?
    /// Whether `key` still describes the capture's file. Consumers call it before applying a result.
    public func isCurrent(_ key: TextMapKey) async -> Bool
}
```

`TextServices` subscribes to the bus on the main actor and forwards each event into one `AsyncStream`, which a single task drains into `handle`, so events reach the store in bus order. `TextServices.maps` exposes the store.

Rules, each a Linux test with `FakeTextReader`, `FakeImageFileReader` and a test clock:
- **Q1.** At most one read runs at a time.
- **Q2.** The next read is the oldest waiting on-demand request, otherwise the **newest** background read (`design/07` §2.7 fix `7f97411`).
- **Q3.** `created` or `edited` for an item that `wanted` accepts queues a background read. `saved` and `moved` update the URL the store reads from (and restart a running read there, Q5b). The store keeps its own id → item mirror from events, and it wins over a stale `item` passed to `map(for:)`.
- **Q4.** `map(for:)`: a cached map whose key matches the file's current fingerprint is returned without a read. A read already running or queued for the same id is joined (a queued background read becomes on-demand). Otherwise a read is queued as on-demand.
- **Q5.** `deleted` removes the capture's queued read, cancels its running read, evicts its map and fails its waiters with `captureGone`. `edited` cancels and evicts the same way, then queues a new read, and the waiters move to it.
- **Q5b.** `saved` or `moved` for a capture whose read is running cancels that read and queues it again at the new URL, at the same priority and with the same waiters (T17). A `.file` read also re-checks the mirror's URL before each strip, so a move between events is caught at the next strip.
- **Q6.** A finished read is stored under the key taken before reading only if the capture is still in the mirror and the fingerprint after the read is the same. If the fingerprint differs with no `edited` event, the read runs once more for its waiters, and a second mismatch fails them with `changedWhileReading`. Discarded results are logged as `dropped`.
- **Q7.** Failures are not cached: waiters get the error and the next request reads again. Empty maps are cached.
- **Q8.** The LRU holds `capacity` maps. A hit refreshes an entry.
- **Q9.** Background reads never delay delivery: they start from `created`, which Capture publishes after save and copy.

### 5.5 In-memory images (`LatestReading`)

`LatestReading` (actor): `read(_ buffer, pixelsPerPoint) async -> TextMap?`. Each call cancels the previous call's read and returns nil if a newer call started before it finished. This is the generation rule of the first build's `EditorTextReader`, for the editor's flattened render in Wave 2. It never caches.
